# Security 0.2 — Cost Protection

**Status:** Source implementation committed; provider-side spend cap and deployed configuration still require owner action.  
**Scope:** request-size guard, output-token ceilings, usage telemetry, and emergency shutdown for the six public AI API routes.

## What changed

1. **Shared request ceiling:** after Vercel has parsed the request body, the backend rejects JSON payloads larger than 256 KiB with HTTP 413 `REQUEST_BODY_TOO_LARGE`. Each route keeps its narrower field-specific validation too.
2. **Chat output ceiling:** Chat Completions requests receive a server-controlled `max_tokens: 2048`; Responses API requests receive `max_output_tokens: 2048`. The client cannot raise these values.
3. **Moderation output ceiling:** the moderation route sends `max_tokens: 256`.
4. **Usage telemetry:** when OpenRouter returns usage metadata, the backend emits a structured `hyperai.openrouter.usage` event with route, model, generation ID when available, token counts, and provider-reported cost when present. Prompt text and generated response text are not logged.
5. **Emergency kill switch:** setting `HYPERAI_AI_ENABLED=false` blocks AI POST requests with HTTP 503 `AI_SERVICE_DISABLED`. The default remains enabled for compatibility when the variable is absent.

No new npm dependency or database was introduced. Existing Upstash rate limiting from Security 0.1 remains a separate layer.

## Provider-side hard spend cap — required operational step

Application-side request limits are defense in depth. **OpenRouter must enforce the actual monetary cap.**

1. Create or select a dedicated OpenRouter API key used only by HyperAI. Do not reuse a personal key shared with unrelated apps.
2. In OpenRouter's API key settings, set a per-key credit/spending limit and an appropriate reset interval (daily, weekly, monthly, or lifetime).
3. If the workspace has budget controls, consider an additional workspace budget or a key-assigned guardrail. These controls stack with the key limit.
4. Keep any Management API key out of HyperAI and out of Vercel runtime variables unless a separately reviewed management workflow truly requires it. HyperAI only needs its normal inference API key.
5. Review the key's remaining allowance and usage in the OpenRouter dashboard. The provider enforces its own limit before paid requests reach model providers.

Official references:
- [OpenRouter Limits](https://openrouter.ai/docs/api_reference/limits)
- [OpenRouter Spend Controls](https://openrouter.ai/docs/guides/best-practices/spend-controls)
- [OpenRouter Management API Keys](https://openrouter.ai/docs/guides/overview/auth/management-api-keys)
- [OpenRouter API response and usage fields](https://openrouter.ai/docs/api_reference/overview)

The project does not choose a dollar amount for the owner. Set a cap that the responsible account owner understands and can afford. A model marked `:free` is not a substitute for a provider-side budget, and optional tools or provider-side fees may have separate pricing.

## Vercel configuration

- Keep `HYPERAI_AI_ENABLED=true` for normal service.
- Set `HYPERAI_AI_ENABLED=false` to stop AI requests during an incident, then redeploy the project so the new environment value is applied.
- Keep `OPENROUTER_API_KEY`, Upstash credentials, and any management credentials server-side. Never expose them through `NEXT_PUBLIC_*`, HTML, browser JavaScript, or client responses.
- Keep `ENABLE_OPENROUTER_WEB_SEARCH=false` unless the owner has reviewed its additional pricing and intentionally enabled it.
- Security 0.1 still requires `UPSTASH_REDIS_REST_URL` and `UPSTASH_REDIS_REST_TOKEN` in Production and Preview. If those values are missing or Redis is unavailable, the limiter fails closed with HTTP 503.

## Telemetry and limitations

- Usage events are operational telemetry, not a complete billing ledger. OpenRouter may omit optional cost fields, and different endpoint types may expose different usage shapes.
- Chat streaming usage is captured from the final Chat Completions usage chunk or the Responses API completion event when supplied by OpenRouter.
- Audio speech returns binary audio; its current route does not emit token/cost usage telemetry.
- The 2,048-token chat and 256-token moderation ceilings are sent as server-controlled upstream parameters. Provider/model support can vary; the OpenRouter provider-side key limit remains the authoritative monetary control.
- This phase does not add per-user quotas or authentication. IP-based rate limiting remains imperfect when many users share one network.
- The 256 KiB check occurs after the Vercel runtime has parsed `req.body`; it is an application validation limit, not a guarantee that oversized bytes are rejected before reaching the function runtime.
- No production load test or real paid generation test was performed as part of this source change.
