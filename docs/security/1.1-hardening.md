# HyperAI Security 1.1 — Hardening Notes

**Status:** Merged to main; not production-certified.  
**Merged commit:** `f7f549e610157215a56947f278c5548cec90d1c7`

## Access sessions

The optional shared-password access gate is implemented in `lib/auth.js` and `api/session.js`.

To enable it in Vercel, configure all of the following before setting `HYPERAI_AUTH_REQUIRED=true`:

- `HYPERAI_ACCESS_PASSWORD`: unique passphrase of at least 12 characters.
- `HYPERAI_SESSION_SECRET`: cryptographically random secret of at least 32 characters.
- `UPSTASH_REDIS_REST_URL` and `UPSTASH_REDIS_REST_TOKEN`: required because login attempts are rate-limited.

The browser obtains a signed 12-hour session cookie with `HttpOnly`, `Secure`, and `SameSite=Lax`. Passwords are not stored in localStorage or sessionStorage. Login is same-origin checked and limited through the existing Redis limiter.

This is a **shared access password**, not individual user accounts. It does not provide per-user identity, MFA, account recovery, or individual audit attribution. The gate remains disabled until the owner explicitly configures the environment variables. When enabled but misconfigured, API access fails closed.

## Daily usage and reported-cost guard

The optional Redis-backed daily guard is available through:

- `HYPERAI_DAILY_REQUEST_LIMIT`: hard count ceiling across all API routes per UTC day.
- `HYPERAI_DAILY_REPORTED_COST_USD`: stops future upstream calls once accumulated provider-reported cost reaches the configured threshold.

These controls are opt-in and require the existing Upstash credentials. The reported-cost guard is **not a hard prepaid spending cap**: usage cost may be missing or delayed, and already in-flight concurrent requests can finish after the threshold is crossed. Use provider-side billing limits for a true financial ceiling. Do not describe the application ledger as a guarantee that the provider bill cannot exceed the configured amount.

## Response resource limits

- JSON upstream responses are read with a 2 MiB ceiling.
- Chat SSE streams are capped at 16 MiB for both supported upstream adapters.
- Speech error text is capped at 16 KiB; successful speech audio retains its existing 8 MiB ceiling.

Oversized upstream bodies are cancelled and mapped to safe public errors.

## CSP migration

A `Content-Security-Policy-Report-Only` baseline is added with restrictive defaults, `object-src 'none'`, and `frame-ancestors 'none'`. It is report-only because the current page still uses inline JavaScript and CSS. The policy deliberately retains `unsafe-inline` during this compatibility phase. It is **not an enforcing CSP** and should not be reported as XSS prevention already completed.

The next CSP step is to move inline scripts/styles to nonce- or hash-based sources, inspect real-browser violations, then introduce an enforcing policy.

## Validation boundaries

Automated tests cover the signed session flow, invalid passwords/origins, fail-closed auth configuration, upstream body limits, budget wiring, frontend session flow, and report-only CSP configuration.

No live Production or Preview validation was performed. The Vercel project remains paused and its latest deployment was previously blocked by the platform build-rate-limit condition. No unpause, deployment, paid AI request, Redis plan change, or billing change is part of this branch.

## Remaining limitations

1. Shared-password access is not a user-account system.
2. Daily reported-cost accounting is post-response and cannot guarantee a maximum provider bill.
3. Daily guardrails remain opt-in until environment values are configured.
4. CSP remains report-only until inline code migration is complete.
5. No real-browser XSS assessment, penetration test, load test, or live deployment validation is claimed.
