# Security 0.8 — Runtime Verification & Redis Operational Hardening

## Scope

Security 0.8 adds a live, low-impact verification path for the Redis Lua scripts already used by HyperAI. It is designed to prove state transitions without sending AI prompts, invoking OpenRouter, changing application-owned keys, or running a load test.

The verifier imports the actual script constants from:
- `lib/rate-limit.js`
- `lib/concurrency.js`
- `lib/resilience.js`

The Lua scripts are exported for reuse by the verifier; their production behavior and thresholds are unchanged.

## Live Redis verification

Run:

```sh
UPSTASH_REDIS_REST_URL="https://your-database.upstash.io" \
UPSTASH_REDIS_REST_TOKEN="your-token" \
npm run verify:redis
```

The script:
1. Validates an HTTPS Upstash REST URL and requires both credentials.
2. Sends an authenticated `PING`.
3. Uses a unique `hyperai:security08:verify:<uuid>:` namespace for temporary keys.
4. Verifies rate-limit atomic increments, TTL behavior, and rejection at the configured test ceiling.
5. Verifies concurrency lease acquisition, limit rejection, release, and reacquisition.
6. Verifies circuit closed/open/half-open states, single-probe locking, and successful reset.
7. Deletes its temporary keys in a `finally` cleanup path.
8. Prints only check labels and generic failure messages; it never prints credentials or raw Redis responses.

The script uses short-lived test TTLs and does not touch HyperAI's live `hyperai:rl:v1:`, `hyperai:concurrency:v1:`, or `hyperai:resilience:v1:` key namespaces.
