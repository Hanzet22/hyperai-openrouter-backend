# Security 0.9 — Upstream Error Boundaries & Regression Gate

## Scope

Security 0.9 hardens the public error boundary between HyperAI and upstream providers. Provider responses and transport exceptions are untrusted input: they must not be reflected to API clients merely because they are short or JSON-encoded.

## Changes

- Adds a shared upstream exception mapper with a small allowlist of known internal resilience states.
- Maps unknown network/provider exceptions to generic HTTP 502 responses.
- Keeps known circuit-open and resilience-store-unavailable states as generic HTTP 503 responses.
- Maps upstream timeouts to a generic HTTP 504 response.
- Replaces raw Responses API SSE error messages with a generic stream failure event.
- Applies the shared mapper to JSON forwarding, chat, and speech transport exception paths.
- Adds regression tests proving that URLs, authorization-like strings, arbitrary status values, and exception messages are not reflected.
- Adds a supply-chain baseline test: the current manifest declares no runtime or development npm dependencies, and workflow actions must be pinned to full commit SHAs.

Provider HTTP error bodies continue to use the existing status-only message from `extractUpstreamMessage`.

## Dependency and workflow review

The current `package.json` declares no runtime or development npm dependencies, and the repository has no package lockfile. The baseline workflow uses commit-SHA-pinned `actions/checkout` and `actions/setup-node` references. A regression test now guards these assumptions; adding a dependency requires an explicit review and lockfile decision.

## Verification

Run:

```sh
npm test
```

The tests are source-level and unit-level regression checks. They do not constitute a real-browser test, provider outage simulation, penetration test, or deployment verification.

## Operational boundary

HyperAI's Vercel project remains paused during this phase. Security 0.9 changes are committed to GitHub only; no deployment, AI generation, OpenRouter request, speech upload, load test, or billing/plan change is part of this phase.
